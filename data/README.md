# PostgreSQL: аккаунты, услуги и транзакции

Готовые данные: **10 аккаунтов, 30 услуг и 100 транзакций**.

## Файлы

- `001_schema.up.sql` — создание трёх таблиц, ограничений и индексов внешних ключей.
- `001_schema.down.sql` — откат: удаление трёх таблиц вместе с данными.
- `data.json` — объект с массивами `accounts`, `services`, `transactions`.
- `002_seed.sql` — загрузка тех же записей в PostgreSQL.
- `generate.py` — генератор JSON и SQL без сторонних Python-библиотек.
- `test_generate.py` — проверки генератора.

## Создание таблиц и загрузка данных

Из каталога распакованного комплекта, указав имя существующей базы:

```bash
psql -X -v ON_ERROR_STOP=1 -d DATABASE_NAME -f 001_schema.up.sql -f 002_seed.sql
```

Для удалённого сервера вместо `DATABASE_NAME` можно передать строку подключения. Параметры пользователя и сервера также можно задавать стандартными переменными PostgreSQL `PGUSER`, `PGHOST`, `PGPORT`.

Миграция рассчитана на отсутствие этих таблиц в схеме `public`. Создание схемы и загрузка данных выполняются отдельными транзакциями: ошибка загрузки не удаляет созданные таблицы. Загрузчик блокирует таблицы на время импорта и отказывается загружать данные, если хотя бы одна таблица непустая. Существующие записи не заменяются. После явной вставки id последовательности переводятся на максимальный загруженный id.

Проверка количества строк:

```bash
psql -X -v ON_ERROR_STOP=1 -d DATABASE_NAME -c 'SELECT (SELECT count(*) FROM public.accounts) AS accounts, (SELECT count(*) FROM public.services) AS services, (SELECT count(*) FROM public.transactions) AS transactions;'
```

Ожидается: `10 | 30 | 100`.

Откат **удаляет таблицы и все содержащиеся в них данные**:

```bash
psql -X -v ON_ERROR_STOP=1 -d DATABASE_NAME -f 001_schema.down.sql
```

## Генерация другого объёма

Нужен Python 3.10 или новее. Команда перезаписывает `data.json` и `002_seed.sql` в указанном каталоге:

```bash
python3 generate.py --accounts 100 --services 300 --transactions 1000 --seed 42 --out ./generated
```

При одинаковых параметрах результат одинаковый. Опорная дата по умолчанию — `2026-10-19T15:00:00.000Z`. Она фиксирована для воспроизводимости; состояния услуг не обновляются с течением времени. Другую дату можно передать через `--reference 2026-11-01T00:00:00.000Z`.

## Принятые решения

- Идентификаторы — `bigint GENERATED BY DEFAULT AS IDENTITY`, начальные значения в JSON — целые числа с 1.
- Имена полей сохранены. В SQL поля с заглавными буквами требуют двойных кавычек: `"ownerId"`, `"createdAt"` и т. д.
- Денежные поля аккаунта и `price` — неотрицательные целые значения в евроцентах, без floating point. `totalReplenished` также трактуется как евроценты.
- `amount` — целое число от 0 до 1000 включительно, согласно заданию. Этот предел закреплён ограничением таблицы. Для проверки границ в первых двух транзакциях стоят 0 и 1000.
- Email уникален с учётом регистра. Используется тестовый адрес вида `user-0001@example.test`. Полную проверку email по RFC схема не реализует.
- Имя услуги допускает только латинские буквы, цифры и дефис. Уникальность имени услуги не требуется и не навязывается.
- Даты в PostgreSQL хранятся как `timestamptz(3)`, в JSON — UTC с тремя цифрами миллисекунд и суффиксом `Z`. Текстовый формат вывода PostgreSQL может отличаться от JSON.
- `expiresAt >= createdAt`. Месяц, квартал, полугодие и год генератор рассчитывает календарно, с ограничением дня последним днём целевого месяца. Интервал задаёт один оплаченный период для тестовой услуги.
- Для `not_performed` допустимо только `performedAt = NULL`; для `performed` обязательна дата не раньше `createdAt`.
- `services."ownerId" → accounts.id`; `transactions."serviceId" → services.id`. Оба внешних ключа используют `ON DELETE RESTRICT` и `ON UPDATE RESTRICT`. История не удаляется каскадно. Статус `deleted` сохраняет строку услуги.
- Значения `withdrawBalance <= balance` и `totalReplenished >= balance` соблюдены в наборе, но не закреплены в схеме: эти бизнес-ограничения не заданы пользователем.
- Данные — синтетические снимки. Балансы не вычисляются из транзакций; транзакции содержат только типы `order` и `prolong`, поэтому полной истории пополнений здесь нет. `amount` генерируется независимо от `price`.

## Проверка комплекта

```bash
python3 -m unittest -v test_generate.py
```

Проверены количество записей, внешние связи JSON, диапазоны, даты, оба статуса транзакций, все периоды и статусы услуг, воспроизводимость и обработка некорректных количеств.

В среде подготовки PostgreSQL отсутствовал: SQL-миграция и импорт на сервере PostgreSQL не исполнялись.
